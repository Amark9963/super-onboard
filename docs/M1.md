# M1 architecture and security notes

M1 adds authenticated staff sessions, organization/project/portfolio/property/contact routes, private source intake, asynchronous parsing, and a source browser. Its scope stops before AI extraction, customer review links, website import, or blueprint generation.

Internal accounts are provisioned through an operator-only CLI. There is no public registration or seeded password. Passwords use salted PBKDF2-SHA256; opaque session tokens are generated with secure randomness, hashed at rest, and sent in HTTP-only, SameSite=Strict cookies. Mutating routes require both an exact configured Origin and a session CSRF token. In production, set `APP_ORIGIN` to the HTTPS frontend origin and `COOKIE_SECURE=true`. Sign-in attempts are limited per account by a database-backed 15-minute window. Sessions expire after eight hours and logout deletes the server-side record.

Every project API requires a live session and explicit project membership, including administrators. Admin role controls membership assignment; it does not bypass membership on project data. Project-scoped objects are queried with `project_id` and cross-project foreign keys backstop writes. Organizations are visible to their creator, their project's members, or administrators. Customer contacts are visible only through their project. Seed data is fictional.

Uploads permit `.pdf`, `.docx`, `.xlsx`, and UTF-8 `.txt` up to 10 MB. The request boundary limits multipart bodies before parsing. Validation checks signatures or Office archives, rejects macros, bounds ZIP expansion, and applies format-specific page/sheet/cell/text limits. Original bytes are kept in a private MinIO bucket under server-generated keys; only an authorized backend route returns them, as attachments with `nosniff` and `no-store`. Source document, version, block, and job records stay separate. Hashes and version numbers preserve provenance.

The worker claims jobs using PostgreSQL row locks, retries transient storage read failures up to three times, and recovers stale claims. Parser work runs in a child process with a timeout and Linux memory/CPU limits. PDF anchors are page numbers; DOCX anchors are headings, paragraphs and table cells; XLSX anchors are sheet/cell addresses; TXT anchors are line numbers; pasted transcripts also retain detected timecodes. No fabricated coordinates or OCR claims are added. Empty/scanned PDFs show `needs_attention`. Parsing failures and error codes remain visible with the source version. Retry is explicit for failed jobs with a stored original.

The UI shows source excerpts as unconfirmed evidence. The M0 mock AI provider remains available only through its adapter/tests and does not create requirements. Project deletion, OCR, full customer review, public website fetch, and generated artifacts are future milestones. Direct database operators and privileged MinIO administrators remain trusted operators; production needs TLS, separate least-privilege storage credentials, external secret management, and restore-tested backups.
