# M5 notes — website import and hardening

M5 adds a bounded, defensive website import and a set of hardening and deployment measures. Everything fetched from a website is **unconfirmed evidence**: it enters the existing parse → extraction → citation check → staff review → customer confirmation → approval pipeline and is never approved, ranked, or trusted because it is public, official-looking, or recent (PRD 5.3, 5.4).

## Website import flow

```text
staff enters a public URL (+ optional approved subdomains, page and depth limits)
  → web_imports (discover_pending)  → worker: robots.txt, sitemap, same-site links
  → web_import_pages: candidates with titles, plus blocked/failed pages with reasons
  → staff selects pages → worker snapshots each one:
       raw bytes in private storage, source_versions row with URL, fetch time, hash, headers summary
  → ordinary ingestion job parses the HTML into blocks (heading paths, table cells) → extraction → review
```

- **Limits (configurable, PRD defaults):** 25 pages, link depth 2 (staff can only lower them), 5 MB per page, 8 s connect / 15 s read timeouts, 3 redirects, 180 s per job, a 0.5 s pause between requests, one request at a time, one active import per project. Discovery fetches candidate pages to read their titles but stores nothing; selected pages are fetched again at import time so the snapshot's timestamp and hash describe exactly what was stored.
- **Scope:** the entered host, its `www`/apex twin, and subdomains staff explicitly approve (which must be subdomains of the entered site). A link, sitemap entry or redirect to anything else is ignored or refused. Only text/HTML pages are imported; PDFs, images, scripts and other files are skipped.
- **Snapshots and versions:** each page is a `web_page` source document named by its URL; changed content creates a new version, identical content creates none. The original bytes are kept, and the version records `source_url`, `fetched_at`, `page_title`, `content_hash` and a small `fetch_meta` (requested URL, redirects, content type, import id).
- **Statuses and reasons:** pages are `candidate`, `queued`, `fetched`, `failed` or `blocked`, each with a content-free reason (`blocked_by_robots`, `not_found`, `unsupported_content_type`, `response_too_large`, `fetch_timeout`, ...). A failed page can be queued again; a blocked page cannot.
- **Evidence from HTML:** the parser (in the existing isolated, time-limited child process) keeps visible text with heading paths and table coordinates. It drops scripts, styles, iframes, templates and **hidden text** (`hidden`, `aria-hidden`, `display:none`, `visibility:hidden`), because text a person cannot see is both poor evidence and a prompt-injection channel. Page text is only ever data: the extraction prompt already tells the model to ignore instructions inside documents, citations are still verified against the stored text, and nothing a page says can set a review or approval state.

## SSRF and fetch safety (`backend/app/webfetch.py`)

| Risk | Defense |
|---|---|
| Non-web schemes (`file:`, `ftp:`, `gopher:`, `data:`, `javascript:`) | only `http`/`https` accepted, at entry and on every redirect |
| Credentials in URLs, control characters, huge URLs | rejected |
| Internal or special addresses | literal IPs and **every** DNS answer must be globally routable; loopback, private, link-local (including cloud metadata `169.254.169.254`), CGNAT, multicast, reserved, documentation, IPv4-mapped/NAT64/6to4/Teredo-wrapped private addresses are refused |
| Alternate IP spellings (`2130706433`, `0x7f.1`, `017700000001`, `127.1`) | numeric-only and hex hostnames rejected outright |
| Internal names (`localhost`, `*.local`, `*.internal`, `*.lan`, `metadata`, single-label hosts) | rejected |
| Dangerous ports (22, 25, 3306, 5432, 6379, ...) | only ports 80 and 443 by default |
| DNS rebinding | DNS is resolved once per hop; the connection goes to that exact validated address (TLS still verifies the certificate against the real hostname); a redirect is a new hop and is resolved and validated again |
| Redirect tricks | manual redirects, 3 at most, each hop re-validated and kept in scope; loops and missing `Location` refused |
| Decompression bombs, huge bodies, slow servers | `Accept-Encoding: identity` and any compressed reply refused; `Content-Length` and streamed bytes capped; per-read and total deadlines |
| Credentials and state leakage | no cookies, `Authorization`, `Referer` or `Origin` are ever sent; the user agent identifies the app |
| Hostile `robots.txt`/sitemaps | RFC 9309 matching (longest match, `*`/`$`, agent-specific group); unavailable robots (4xx) allows, server errors/timeouts disallow; unsafe redirects are reported as security failures, not robots verdicts; sitemaps parsed with `defusedxml` (DTDs/entities refused), 2 MB cap, 500 URLs |

`WEB_PRIVATE_HOST_ALLOWLIST` is a **development/test-only** switch that lets named hosts resolve to private addresses (the demo `fixture-site` container and the test servers use it). It must stay empty everywhere else; `compose.prod.yaml` forces it empty. An allowlisted host does not widen the policy for any other host.

**Honest limits:** the fetcher resolves DNS with the system resolver (no DNSSEC, no DoH). It does not render JavaScript, so single-page sites without server-rendered text import little. Discovery follows ordinary links only. It does not read `crawl-delay`, honor `X-Robots-Tag`/meta `noindex` for importing (only `nofollow` for link following), or log in to anything. TLS is verified with the platform CA store.

## Hardening added in M5

- **Per-client rate limits:** public review routes and sign-in are now limited per client address (300 and 40 per 15 minutes by default) in addition to the per-token and per-account limits. The client address comes from `X-Forwarded-For` **only** when `TRUSTED_PROXY_HOPS` says how many proxies you run; the entry that many places from the right is used and anything a client prepends is ignored (default 0 = header ignored).
- **Security headers** on every web response (nosniff, frame denial, a partial CSP with `frame-ancestors 'none'`, referrer and permissions policies, COOP); review links keep `no-referrer`, `no-store` and `noindex`.
- **Containers:** the backend image runs as an unprivileged user.
- **Dependencies:** `pypdf`, `python-multipart` and `pydantic-settings` were upgraded because `pip-audit` reported advisories against the pinned versions (the first two parse untrusted uploads); `defusedxml` was added. `pip-audit` and `npm audit --omit=dev` are clean as of the verification record; bandit reports nothing at medium severity or above.
- **AI provider URL** must be http(s); `file:` and custom schemes are refused.
- **Deployment and recovery:** `compose.prod.yaml`, `infra/caddy/Caddyfile`, `scripts/backup.sh` and `scripts/restore_check.py` (see [DEPLOYMENT.md](DEPLOYMENT.md)). The restore check actually restores a dump into a scratch database and compares migration revision, per-table row counts and trigger counts.
